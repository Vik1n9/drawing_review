本專案沒有使用任何 Python logging 模組或第三方日誌框架，所有「記錄」行為都以 `print()` 直接輸出到標準輸出／錯誤。為確保在 Windows 環境下中文能正確顯示，專案提供了一個專門的編碼處理工具 `tools/console.py`，並透過測試強制每個 CLI 工具自行呼叫它。

### 使用的系統與方法
- **標準庫 `print()`**：所有工具的診斷訊息、進度提示、錯誤說明都直接用 `print()` 輸出，不經過任何 logger 實例。
- **`tools/console.force_utf8_output()`**：唯一負責串流編碼設定的函式，會把 `sys.stdout` 與 `sys.stderr` 以 `reconfigure(encoding="utf-8", errors="replace")` 重設為 UTF-8，失敗一律吞掉以免影響工具執行。
- **批次檔層級設定**：安裝器與發版腳本產生的 `.bat` 會先執行 `chcp 65001` 與設定 `PYTHONUTF8=1`，讓雙擊啟動的使用者也能正確顯示中文。

### 關鍵檔案與套件
- `tools/console.py`：定義 `force_utf8_output(streams=None)`，是整個專案唯一處理 stdout/stderr 編碼的地方。
- `tests/test_console_encoding.py`：靜態檢查每個含 `__main__` 的工具都有呼叫 `force_utf8_output()`；並以子行程模擬 cp1252 管道實測所有工具不會因編碼崩潰。
- `tools/installer.py`、`tools/onboarding.py` 等 CLI 工具：開頭統一 `from tools.console import force_utf8_output; force_utf8_output()`。
- `tools/make_release.py`、`tools/make_sfx.py`：產出的 `.bat` 模板內寫死 `chcp 65001` 與 `PYTHONUTF8=1`。

### 架構與慣例
- 沒有集中式 logger 初始化，也沒有 log level、formatter、handler 的概念。
- 每個 CLI 工具獨立負責自己的輸出編碼，靠 `test_console_encoding.py` 的靜態掃描與子行程實測來維運一致性。
- 錯誤訊息直接印到 stderr（例如 `UnicodeEncodeError` 的追蹤），成功訊息印到 stdout，沒有結構化欄位或 JSON 格式。

### 約束與規則
- **每支 CLI 工具必須自行呼叫 `force_utf8_output()`**：由 `tests/test_console_encoding.py::EveryCliToolDeclaresItTest` 以讀取原始碼的方式斷言，避免依賴 import 副作用。
- **輸出一律用繁體中文**：測試中用包含 emoji 與全形標點的樣本字串驗證不會觸發 `UnicodeEncodeError`。
- **errors="replace" 刻意为之**：遇到無法以 UTF-8 表示的字元時以替代字元輸出，好過整個流程中斷——診斷工具自己壞掉比漏報更糟。
- **零安裝主線**：除編碼處理外不引入額外相依，確保在任何 Python 環境都能執行。

由於完全沒有使用 `logging` 模組、沒有結構化日誌欄位、沒有 log level 管理，本倉庫的「日誌系統」實質上就是「受保護的 print() 輸出」。
