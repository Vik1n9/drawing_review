- 差異清單每筆 finding 固定包含 `id`（D-NNN-01 格式）、`status`（pending / decided）、`target_file`、`rule_id`、`equipment`、`article`、`type`、`current_value`、`difference`、`impact`、`suggested_fix`、`note`、`auto_fix`（tests + params）與 `manual_steps` 等欄位。
- 核定結果 JSON 一律以 `results-{YYYYMMDD}[-{規則檔}].json` 命名，頂層必填 `verified_by`、`verified_date`，可選 `evidence` 指向掃描檔路徑，`results` 陣列內每筆含 `rule_id`、`result`（correct / incorrect）、可選 `note`。
- 規則參數修正必須走先紅再綠：先改 `rule_tests.json` 的 `expected` 使測試轉紅，確認失敗後再改規則參數使測試轉綠，最後才以 `apply` 回填 `verified: true`，禁止直接手改 JSON 跳過確認紀錄。
- 待確認清單中仍有未裁示差異的規則會被 `apply` 拒絕回填；裁示為「維持現值」時需在該筆 results 加 `override_discrepancy: true` 並在 `note` 寫明理由。
- 所有追溯檔（差異清單、核定紀錄、註解紀錄）皆以日期戳記（YYYYMMDD）區分版本，並保留原始比對依據（source_of_truth 列出法條全文、附表 PDF/PNG 等）。
