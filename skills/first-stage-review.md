# 第一階段：複合用途建築物及樓層屬性檢討

對 $ARGUMENTS（案件名）執行消防審圖**第一階段**：自建築師提供的文件擷取建築物基本資料與
各樓層用途，依《各類場所消防安全設備設置標準》第 12 條與《複合用途建築物判斷基準》附表
判定複合用途類別與樓層屬性，產出檢討表（HTML ＋ Excel 兩式）。

**第一階段未完成前不得執行 `/stage-two-review`。** §12 分類直接決定所有設備門檻。

## 與既有 skill 的關係

本 skill 是**兩階段工作流程的第一階段包裝**，不重造輪子，而是串接既有 skill 並加上
兩道關卡與 Excel 交付物：

| 步驟 | 執行 | 產物 |
|------|------|------|
| 1. 收件與逐層萃取、證照文件萃取 | `/plan-intake` | `case.json` 草稿 |
| 2. §12 分類與主從用途定案（人工確認關卡） | `/mixed-use-review` | `case.json` 定案 |
| 3. **受控自動化關卡** | `tools/case_facts_gate.py --stage first` | ready / 阻擋問題 |
| 4. 交付物產出 | `mixed_use_report.py` ＋ `stage_report_xlsx.py first-stage` | HTML ＋ Excel |

## 開場前置檢查（訓練成果與圖譜新鮮度）

```bash
python3 tools/training_intake.py status
```

結束碼 `2` ＝ 圖譜未跟上規則庫（或有未完成的重建）。此時**先補建圖譜再續行**，
否則查圖譜會查到舊資料。輸出同時會告知：最新訓練批次、Active 修正筆記數、
現有實務註解數、尚未逐條確認的規則數。

## 開始前必讀（不可跳過）

檢視任何案件文件**之前**，完整讀取 `rules/review_corrections.md`，並套用所有
`Status: Active` 且適用於本案的條目。優先序：

1. 使用者當下指示
2. 現行法規與本案核准文件
3. `rules/review_corrections.md` 中適用且 Active 的條目
4. 本 skill 其餘規則
5. 舊範例與專案流程筆記

使用者明確指出第一階段結果有誤並提供／確認正確做法時，**先套用修正到當前工作**，
再依 `rules/review_corrections.md` 的「使用規則」追加新條目（保留全部既有條目，
不得刪除歷史），完成後簡短告知使用者。**不得記錄未經使用者確認的推定。**

## 輸入

建築師常提供的文件（缺任何一項都不阻擋審查，但缺漏須明確標示）：

- 使用執照——用途分類與原核准面積的最高優先證據
- 室內裝修（合格證明）申請書
- 變更使用申請書
- 樓層附表、剖面圖或其他載有逐層高度的核准文件

擷取欄位對應 `case.json` 的 `use_permit`／`interior_renovation`／`change_of_use`／`floors`
三＋一區塊，欄位定義見 `skills/plan-intake.md` 第四步 schema。

## 正規化規則

- **變更用途案件**：`各層用途` 記載變更前／原核定用途；`各層變更後用途` **僅**填有變更的
  樓層，未變更樓層留白。變更僅涉及某層一部分時，保留原核定用途、於變更後用途欄標示變更
  後用途、於申請範圍面積欄填變更範圍面積，剩餘原用途面積可確認時記於備註。
- **不得以建築物使用類組代碼（F3、G3、H2 等）作為第 12 條分類依據**，一律依實際場所名稱
  與第 12 條明文判斷；輸出表中移除代碼（`H2集合住宅` → `集合住宅`）。
- `停車空間` 與 `專用停車場` 在本工作流程視為同義，連同`依法附設之室內停車空間`
  一律列為**從屬用途**，不得僅因出現在樓層表就當作獨立主要用途，除非使用者明示該停車
  用途為獨立主用途。
- **所有地上樓層一律列為`無開口樓層`**（`rules/review_corrections.md` 2026-07-14 通案規則），
  地下層維持`地下層`，屋突／屋頂層維持`屋頂層`。
- 備註欄只對本次申請樓層填 `本次申請範圍`，其他列留白。

## 分類規則（第 12 條）

依 `skills/place-use-classification.md` 與 `rules/法規/各類場所消防安全設備設置標準第十二條.docx`
判定，常見對應：

- 集合住宅：乙類第 7 目
- 文教設施（學校、教室、訓練相關）：多為乙類第 3 目，有實際場所名稱時以名稱為準
- 辦公室：乙類第 6 目
- 停車空間、專用停車場、依法附設之室內停車空間：第一階段列為**從屬用途**
- 複合用途建築物中有甲類用途：戊類第 1 目
- 無甲類，但含第 2 至第 4 款場所：戊類第 2 目
- 地下建築物：戊類第 3 目（適用時）

**每一項分類都必須明示第 12 條的款、目及類別**。全棟僅一種用途時，結論用
**「單一用途建築物」，不用「非複合用途建築物」**。

## 執行流程

### 第一步：收件與萃取

```bash
# 尚未建立 case.json 時
/plan-intake {案件名}
```

### 第二步：§12 分類與主從用途定案

```bash
/mixed-use-review {案件名}
```

第 12 條分類只產生候選，**最終以人工確認後的 `case.json` 為準**。定案後
`building.mixed_use_assessment` 的 `source` 必須為 `manual`。

### 第三步：受控自動化關卡（強制，不可跳過）

```bash
python3 tools/case_facts_gate.py --stage first --case output/{案件名}-{YYYYMMDD}/case.json
```

回傳 `ready: false` 或結束碼 2 時，**不得輸出最終交付物**。逐項向使用者詢問 `questions`
內容、更新 `case.json` 後重新檢查。**不得以猜測、預設值或未提供的圖說補足資料。**

### 第四步：產出交付物

```bash
# 交付物 4（HTML，專案固定交付物）
python3 tools/mixed_use_report.py --case output/{案件名}-{YYYYMMDD}/case.json

# 第一階段工作簿（Excel，兩階段工作流程交付物）
python3 tools/stage_report_xlsx.py first-stage --case output/{案件名}-{YYYYMMDD}/case.json
```

## 工作簿格式契約

格式權威為 `input/範例/第一階段-複合用途及樓層屬性檢討-格式範本.xlsx`。四個分頁固定為
`複合用途檢討`、`用途判斷依據`、`來源資料`、`各樓層高度`。

**`複合用途檢討` 主表**欄位順序固定為：
`樓層｜各層用途｜樓地板面積(m²)｜各層變更後用途｜本次申請範圍樓地板面積(m²)｜樓層屬性｜備註`

- 最後一筆實際樓層後**僅保留三列空白**，其後為合計列，再一列空白間隔，最後才是判定區。
- `樓層屬性`（F 欄）清單驗證：`地下層`、`無開口樓層`、`屋頂層`、`一般樓層` 與**空白**。
  空白是刻意保留的——證據不足的列維持未分類，**嚴禁以推測填充**。
- `備註`（G 欄）清單驗證：`本次申請範圍` 與空白。
- **判定區採結構化兩欄表**：每一項適用的第 12 條分類各佔左欄一列，不得合併成散文；
  右欄清單驗證 `單一用途建築物`／`戊1複合用途建築物`／`戊2複合用途建築物` 與空白，
  判定只在第一列填一次。第二階段直接取用這些結構化列，**不得從自由文字重建**。

**`各樓層高度` 分頁**：

- 主表每一樓層都要有列，樓層名稱與順序一致，缺高度也不得省略。
- 高度存為**數值（公尺）**，儲存格內不放單位。
- `資料來源` 註明來源檔案與頁次或圖號。
- **不得以建築物高度平均或相除推算樓層高度。** 無資料時 `樓層高度(m)` 留白，
  於備註標 `未提供`／`無法辨識`／`不適用`。
- 優先採核准樓層附表明載的樓高，其次核准剖面圖，再其次其他核准文件。核准來源互相矛盾時
  **不得逕自擇一**：相鄰兩列分別記載並各自註明來源，備註標 `來源不一致，待覆核`。

## 完成契約

使用者要求執行第一階段時，**不得停在分析、預覽表格或對話式摘要**，除非使用者明示不要匯出。
一次成功的執行必須全部滿足：

1. `output/{案件名}-{YYYYMMDD}/` 下產生 HTML 檢討表與 `.xlsx` 工作簿
2. 工作簿含 `複合用途檢討`、`用途判斷依據`、`來源資料`、`各樓層高度` 四分頁
3. 版面依格式範本，未從空白表新造
4. 主表已檢查數值與公式錯誤
5. `各樓層高度` 含主表每一樓層、順序一致、已檢查
6. `case_facts_gate.py --stage first` 回傳 `ready: true`
7. 最終回覆連結產出的檔案

任何輸入缺漏時，仍以現有資料產出工作簿並清楚標示不確定或缺漏值。真的無法產生檔案時，
明確回報為受阻並說明失敗的確切原因。

## 驗證清單（回覆前）

- 已在檢視案件文件前讀取 `rules/review_corrections.md`，並套用適用的 Active 條目
- 樓地板面積合計與使用執照勾稽
- 本次申請範圍面積與申請書勾稽
- `各樓層高度` 含主表每一樓層且順序一致；已填高度為數值、附來源；缺漏者留白並標狀態
- 樓層高度與所引樓層附表／剖面圖比對，明顯離群值已查證；**不得為湊合建築物高度而硬套**
- 主表與 `各樓層高度` 已算圖或檢視，確認可讀性與格式一致
- 掃描公式錯誤（`#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`）零命中
- 報告標頭注明法規版本（`rules/*.json` 的 `regulation_version`）
- 援引 `rules/review_corrections.md` 做成的結論已附「本判斷慣例未經消防專業人員核定，
  以現行法規為準」警語

## 常見錯誤

- 未先讀 `rules/review_corrections.md` 就開始看案件文件
- 把未經確認的假設寫成修正筆記
- 表中殘留 H2／D2／G2 等使用類組代碼
- 每一列都填備註（只有本次申請樓層該填）
- 使用者已定義為無開口樓層的地上層仍標「待確認」
- 把 `停車空間` 與 `專用停車場` 當成兩個概念，或把停車用途當主要用途分類
- 格式範本可用時卻造出視覺上全新的工作簿
- 因缺高度就把樓層從 `各樓層高度` 漏掉；或用建築物高度平均推算樓層高度
- 數值高度儲存格內混入 `m` 等文字
- 中間版、測試版工作簿留在案件輸出資料夾（算圖與 QA 產物只放暫存目錄）
